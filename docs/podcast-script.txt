DAVID: Not seats. The free plan has no seat data, so availability, waiting lists and fares are simulated. And there is no free public way to actually book an Indian train ticket, so booking is a simulation too. The screen says so on every train.
ZIRA: What about the quota? I heard it is small.
DAVID: A hundred requests a month. So every route is cached for a day, a failure is remembered for an hour, and when the budget runs out the app quietly falls back to its built in timetable.
ZIRA: Good. Now the six new modules. Hotels first.
DAVID: Hotels and homestays with per night inventory. If you stay three nights, each of those three nights must have a free room. The check out day stays free for the next guest. When you start booking, the room is held for ten minutes while you pay. If you walk away, the hold lapses and the room comes back.
ZIRA: And the hotel listings themselves?
DAVID: Generated sample data, clearly labelled sample. The booking logic is real, the hotels are not.
ZIRA: Next, payments.
DAVID: A mock gateway with test cards and U P I. Money is stored as whole paise, never decimals, so there are no rounding surprises. Every payment carries an idempotency key, so a double click or a retry never charges you twice. Webhooks are signed, with replay protection. And cancelling follows refund tiers into a wallet.
ZIRA: No real card numbers anywhere.
DAVID: None entered, none stored.
ZIRA: Crowd forecasting and reviews?
DAVID: A calendar scores each day from festivals and season, and that score feeds dynamic hotel pricing. Reviews are only for travellers with a completed booking. Photos are re encoded so hidden location data is stripped, ratings use a Bayesian average so one five star review does not beat a hundred good ones, and people can report abusive reviews.
ZIRA: Then group trips, my favourite.
DAVID: Friends join a trip and add expenses. The app splits each expense exactly, using a largest remainder method so the paise always add up. Then settle up works out the fewest payments: match the biggest debtor with the biggest creditor, repeat. For n people that is at most n minus one transfers.
ZIRA: And if two people edit at once?
DAVID: The second edit gets a conflict message instead of silently overwriting the first. That was a bug we caught and fixed.
ZIRA: Now the headline feature. The A I trip planner.
DAVID: You type something like, four days, Madurai and Rameswaram, two travellers. The planner is ordinary code. It finds the best order of towns with a dynamic programming method called Held Karp, schedules stops inside real opening hours, and keeps the budget in check.
ZIRA: So where does the language model come in?
DAVID: Only for wording. The code decides every fact. The model writes the friendly intro, a summary and a tip for each day. Then a fact checker rejects any sentence that contains a time, number or place that is not in the plan. If the model slips, the app uses template wording instead.
ZIRA: That makes the model almost safe to be wrong.
DAVID: Exactly the point.

ZIRA: But it can run one.
DAVID: A small model, quantised to four bits, around one and a half billion parameters, should run on the C P U at roughly five to ten tokens a second.
